# Napoleon's theorem in Lean 4

A Lean 4 + Mathlib formalisation of **Napoleon's theorem** in the complex plane, for both the outer
and the inner Napoleon triangles, stated with distances.

> For any triangle `ABC` in `ℂ`, the centres of the equilateral triangles erected on its sides
> (all outward, or all inward) form an equilateral triangle.

`apex ω P Q = P + ω(Q − P)` erects the equilateral triangle on `PQ`, with `ω = ωo = e^(−iπ/3)`
(outer) or `ωi = e^(iπ/3)` (inner); `Ga, Gb, Gc` are the centroids. The key step is
`Gb − Ga = ω (Gc − Ga)`, a `linear_combination` certificate.

**Status:** all statements proved, with no `sorry`. `gate.sh` checks 13 named declarations.

## Main statements

| Lean name | File:line | Statement |
|---|---|---|
| `Napoleon.napoleon_outer` | `Napoleon/Basic.lean:98` | Napoleon's theorem, outer triangle: `dist Ga Gb = dist Gb Gc = dist Gc Ga` |
| `Napoleon.napoleon_inner` | `Napoleon/Basic.lean:104` | the same for the inner triangle |
| `Napoleon.napoleon_general` | `Napoleon/Basic.lean:81` | for any `ω` with `ω² − ω + 1 = 0`, `‖ω‖ = 1`, `‖1 − ω‖ = 1` |
| `Napoleon.apex_equilateral` | `Napoleon/Basic.lean:64` | the erected triangles are equilateral |
| `Napoleon.apex_outward` | `Napoleon/Basic.lean:112` | orientation: `signedArea P Q (apex ωo P Q) = −(√3/4)·‖Q − P‖²`, so for counter-clockwise `ABC` the `ωo` triangles are outward |

No non-degeneracy hypothesis is needed. A non-vacuity `example` (triangle `0, 1, i`, with a
nonzero Napoleon side) is at `Napoleon/Basic.lean:119`.

## Verification

`./gate.sh` builds the library and generates its own `#print axioms` queries for 13 named
declarations, fully qualified (every declaration cited in `SPIKE_REPORT.md`, plus every name
queried by the axiom scratch file `scratch/Ax.lean`). The queries are generated by the gate itself, not read
from a file in the repository.

The gate fails if any of the following is true:
- a source file (`Napoleon/*.lean`, `Napoleon.lean`) contains `sorry`, `admit`, `native_decide`, `axiom`, `#eval`, `run_cmd`, `initialize`, `IO`, `set_option`, `macro`/`elab`/`syntax`/`notation`/`infix`/`prefix`/`postfix`, `import Lean` or `open Lean`;
- the build fails;
- a named declaration is missing, or has an extra report;
- a named declaration depends on anything other than `propext`, `Classical.choice` and `Quot.sound`.

Output: `PASS (13 declarations, standard axioms only)`. Some of these are definitions, which may
use a subset of the three axioms.

`tests/tamper.sh` plants six kinds of fake proof in scratch copies (in `Napoleon/Basic.lean`) and checks
that the gate rejects each one (a rejection must exit nonzero and print the expected `FAIL`
message). The real repository is never modified.

| Test | What it plants |
|---|---|
| sorry | a `sorry` |
| ax2line | an axiom split across two lines |
| evalfake | an `#eval` that prints a fake axiom report |
| macro | a custom macro that rewrites `#print axioms` |
| falsehyp | the hypothesis `‖1 − ω‖ = 1` dropped from `apex_equilateral` (false, e.g. for `ω = −1`) |
| wrap | a genuine extra axiom with a long name, so the report wraps over several lines |

`tests/tamper.sh` needs a prior `lake build` (it reuses `.lake/build`); run the tests one at a time.

`python3 code/check_napoleon.py` checks both versions on 1000 random triangles, with negative
controls (a 50° rotation; mixed orientations). `SPIKE_REPORT.md` is the development log.

## Prior art

Napoleon's theorem is already formalised, and this development makes no novelty claim. A Lean 4
repository by Imran Tanrıkolu ([Napoleon-s-Theorem-in-Lean4](https://github.com/imran-tanrikolu/Napoleon-s-Theorem-in-Lean4))
proves the algebraic criterion `Σ(zᵢ − zⱼ)² = 0` for one rotation. The Isabelle AFP entry
*Napoleon's Theorem* (Ramos, Hulak and de Queiroz) uses complex coordinates, with both orientations;
Guilhot's Coq development treats it in `point_napoleon.v`. Relative to the Lean repository, this
version states equality of distances and proves both Napoleon triangles and the orientation lemma.

## Build

```sh
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh   # if Lean is not installed
lake exe cache get
lake build
./gate.sh
bash tests/tamper.sh
```

Toolchain: Lean `v4.33.1`, Mathlib `v4.33.1` (revision pinned in `lake-manifest.json`).
`gate.sh` never fetches: run `lake exe cache get` (or `lake build`) first so that the pinned
Mathlib checkout is present in `.lake/packages`.
